# Research state and bounded replacement

The shared research policy separates per-source progress from the final stage result. Runtime `source_states` records provider request status, target HTTP status, usable text, coverage, identity assessment, independence, accepted fact count and qualification. `research_sufficiency` records the source target, remaining active issues, historical issues and stopping reason. These diagnostics are visible in child execution state; the existing public dossier schema remains unchanged and keeps all issues.

Page admission checks classification, source target, round/page limits, shared-service stop and remaining time before removing a candidate or incrementing attempted pages. When the first round misses its target, a second institutional search is attempted within the remaining search/time budget before spending the remaining page allowance. Existing queued candidates remain a fallback and are ranked together with new candidates. The second-round page chain can loop through remaining candidates until enough usable pages are collected, the queue empties or a budget prevents admission. Model assessment still determines qualification; usable text alone is not a qualified source. The existing two research rounds remain the bound: no new unlimited extraction rounds were added.

Research success now means the qualified-source target is met with no remaining active evidence issue. Failed candidate access and empty-page/search/model attempts are retained as historical issues and do not alone force partial after recovery. Truncation or rejected facts affecting qualified evidence still cause partial. An uncertain/duplicate source does not count. No facts means failed; partial evidence without the target means partial. Success is not a claim of complete factual verification.

Regression tests cover denied admission without consuming candidates, page cap, shared stop, queued-candidate reuse, recovered 403, active truncation, uncertain independence and empty evidence. The n8n refill scenario configures a four-page budget: the first two targets return 403, the remaining two qualify, the second search stays within budget, and Research succeeds while retaining both access-denial issues. Existing mixed/stop/intake scenarios remain required.

All changes are local; no paid provider requests are needed for these tests. Rebuild workflow JSON before importing so every generated node receives the same shared policy. A real-web run of the new policy has not yet been performed.
